# C++ 类与对象核心知识点总结

## 一、 构造函数与默认构造函数

1. **默认构造函数的分类与冲突**
   * **默认构造函数的定义**：不用传参数就可以调用的构造函数统称为默认构造函数。主要包括三种：
     1. 无参构造函数
     2. 全缺省构造函数
     3. 不显式定义构造函数时，编译器自动生成的构造函数
   * **歧义问题**：无参构造函数与全缺省构造函数**不能同时存在**，否则在无参实例化对象时会导致编译器的调用歧义。

2. **默认构造函数的局限性与特例**
   * **常见情况**：大多数情况下如果不手写构造函数，编译器自动生成的默认构造函数无法满足我们的资源初始化要求。
   * **经典特例（两个栈实现一个队列 `MyQueue`）**：
     * 在 `MyQueue` 类中，成员变量为两个 `Stack` 对象。这里的 `Stack` 变量属于**自定义类型**。
     * 当实例化 `MyQueue` 时，编译器生成的默认构造函数会自动去调用 `Stack` 类内部的默认构造函数来完成初始化。

3. **内置类型与自定义类型的构造行为**
   * **生成条件**：当内置类型和自定义类型混合在类中，且未显式给定任何带参构造函数时，编译器都会自动生成默认构造函数。
   * **内置类型的处理**：对于内置类型，不写构造函数时编译器**不做处理**。变量呈现为随机值并非编译器主动赋值，而是编译器直接忽略了该内存块的初始化，读取到了内存中原本残存的垃圾值。
   * **自定义类型的处理**：对于自定义类型成员变量，编译器要求必须调用其自身的默认构造函数来进行初始化。如果该自定义类型只提供了带参构造函数，且未显式传入参数（或未指定缺省值），会导致找不到可调用的默认构造函数从而引发编译报错。

4. **构造函数的重载与功能**
   * **功能定位**：构造函数类似于传统 C 语言中的 `Init` 函数功能。
   * **重载特性**：构造函数本质上也是一种成员函数，**可以进行函数重载**（例如同时定义无参构造和带参构造）。

## 二、 析构函数与资源管理

1. **析构函数的功能与唯一性**
   * **功能定位**：析构函数类似于传统 C 语言中的 `Destroy` 功能，用于完成对象销毁前的清理工作。
   * **不可重载**：析构函数没有参数，**无法进行函数重载**。一个类中有且仅有一个析构函数。

2. **析构顺序**
   * 当一个作用域内实例化了多个对象时，对象的销毁遵循栈的后进先出（LIFO）原则：**先定义的对象后析构，后定义的对象先析构**。

3. **内置类型与动态资源的析构**
   * **无资源申请时**：析构函数只对有资源申请的类进行具体操作，对于单纯的内置类型不做处理。
   * **有资源申请时**：在有资源释放需求（如通过 `malloc` 或 `new` 申请内存）的前提下，如果不显式手写析构函数，编译器虽会自动生成默认析构函数，但它**无法释放 `malloc` 或 `new` 申请的堆区空间**，最终会导致内存泄漏。

4. **自定义类型成员的析构行为**
   * **自动调用机制**：在 `MyQueue` 这类包含自定义类型成员（如 `Stack`）的类中，无论你是否显式编写 `MyQueue` 的析构函数，编译器在执行完 `MyQueue` 析构函数后，**都会自动去调用自定义类型成员自身（`Stack`）的析构函数**。

## 三、 类的默认成员函数与运算符重载

1. **类的默认成员函数**
   * C++ 类中一共包含 **六个默认成员函数**（在用户未显式定义时由编译器自动生成）。

2. **运算符重载规则**
   * **作用对象**：`operator` 运算符重载针对的是**至少包含一个自定义类类型操作数**的情况，对纯内置类型无任何影响（无法改变内置类型的固有逻辑）。
   * **参数匹配原则**：运算符表达式中的左侧操作数传递给函数的第一个参数，右侧操作数传递给第二个参数。
   * **类内重载机制**：当运算符重载定义在类内部时，成员函数的第一个参数默认是隐式的 `this` 指针，因此在显式形参列表中**需要少写一个参数**。
